# ROS 2 Transform ツリーとオドメトリ

## 学習目標

このチュートリアルを修了すると、以下の内容を習得できます：

- カメラの位置を **TF ツリー**の一部として配信する Transform パブリッシャの追加
- オブジェクトの**相対姿勢**の配信
- ロボットの**オドメトリ**の配信と `world -> odom -> base_link -> 各リンク` の TF 構成
- メニューショートカットによる Transform / オドメトリパブリッシャの自動生成
- **複数センサー**を RViz2 でまとめて可視化する方法
- Isaac Sim 内での TF ツリーの可視化（**TF Viewer**）

## はじめに

### 前提条件

- [チュートリアル 1: URDF インポート: Turtlebot](01_urdf_import_turtlebot.md)、[チュートリアル 5: ROS 2 カメラ](05_camera.md)、[チュートリアル 8: RTX Lidar センサー](08_rtx_lidar.md)を完了していること
- [ROS 2 セットアップ](00_setup.md)が完了しており、Isaac Sim 起動前に必要な環境変数が設定され、ROS 2 エクステンションが有効であること

### 所要時間

約 25〜30 分

### 概要

ROS 2 のシステムでは、ロボットの各リンク・センサー・地図座標系の位置関係を **TF（Transform）ツリー**として管理します。このチュートリアルでは、Isaac Sim から TF を配信するノードの使い分けと、ナビゲーションに必須の**オドメトリ**配信を学びます。

!!! note "TF 配信に使うノードの役割分担"
    | ノード | 役割 |
    |---|---|
    | **Isaac Compute Transform Tree** | ステージ上のプリム（`targetPrims`）の階層を走査し、親子フレームと姿勢（並進・回転）の配列を**計算**する。アーティキュレーションルートを指定すれば配下の全リンクを自動展開 |
    | **ROS2 Publish Transform Tree** | Compute ノードが計算したフレームと姿勢の配列を受け取り、TF として**配信**する |
    | **ROS2 Publish Raw Transform Tree** | プリムとは無関係に、**指定した親フレーム→子フレームの変換を 1 つだけ**配信。`odom -> base_link` や `world -> odom` のような論理的なフレームの接続に使う |

!!! warning "6.0 での変更点：targetPrims の直接入力は非推奨"
    Isaac Sim 6.0 以降、**ROS2 Publish Transform Tree** ノードはプリムを内部で解決せず、**Isaac Compute Transform Tree** ノード（`isaacsim.core.nodes`）が事前計算したフレームを受け取る構成になりました。Publish ノードへの直接のプリム入力（`targetPrims`）は非推奨（deprecated）で、将来のリリースで削除される予定です。5.1 以前のグラフを移行する場合は、公式の [Migrating ROS2 Publish Transform Tree](https://docs.isaacsim.omniverse.nvidia.com/latest/migration_guides/isaac_sim_6_0/ros2_omnigraph_migration.html) を参照してください。

## ステップ 1：Transform ツリーパブリッシャ

[チュートリアル 5](05_camera.md) でステージに追加した 2 台のカメラを TF ツリーに追加し、グローバルフレームでのカメラ位置を追跡できるようにします。

1. Stage パネルで `/World` を選択します（新しい Action Graph が、配信対象のカメラ群の隣に作成されます）。**Window > Graph Editors > Action Graph** を開き、**New Action Graph** をクリックしてグラフ名を `ROS_CameraTF` にします（グラフのパスは `/World/ROS_CameraTF`）。
2. グラフに **Isaac Compute Transform Tree** ノードと **ROS2 Publish Transform Tree** ノードを追加します。**On Playback Tick** を Compute ノードの **execIn** に、**Isaac Read Simulation Time** を Publish ノードの **timeStamp** に接続します。
3. Compute ノードの出力を Publish ノードに接続します：**execOut → execIn**、**parentFrames → parentFrames**、**childFrames → childFrames**、**translations → translations**、**orientations → orientations**。
4. **Isaac Compute Transform Tree** ノードの Property タブで、**targetPrims** フィールドに `Camera_1` と `Camera_2` の両方を追加します。
5. ROS 2 ターミナルで TF ツリーを確認します：

    ```bash
    ros2 topic echo /tf
    ```

    両方のカメラが TF ツリーに載っていることを確認し、ビューポート内でカメラを動かして姿勢の値が変化することを観察してください。

![TF グラフ](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_6.0_ros_tut_gui_ros2_camera_tf_graph.png)

### アーティキュレーションの Transform

関節を持つロボットの**全リンクの Transform** を配信するには、ROS2 Publish Transform Tree に接続した **Isaac Compute Transform Tree** ノードの `targetPrims` に、ロボットの**アーティキュレーションルート**を追加します。アーティキュレーションルート以下のすべてのリンクが自動的に配信されます。

!!! warning "TF ツリーのルートリンクが間違っている場合"
    生成された TF ツリーが誤ったリンクをルートにしている場合は、アーティキュレーションルートを手動で付け替えます：

    1. Stage ツリーでロボットのルートプリムを選択し、**Raw USD Properties** タブの **Articulation Root** セクションを、セクション右上の X をクリックして削除します。
    2. 望みのリンクを Stage ツリーで選択し、**Raw USD Properties** タブの **+ADD** ボタンから **Physics > Articulation Root** を追加します。
    3. 変更後、ファイルを保存してリロードします。

### 相対 Transform の配信

Transform は既定で**ワールドフレーム基準**です（Turtlebot の `/base_link` は `/World` 基準で配信されています）。カメラなど別の基準で Transform を取得したい場合は、**Isaac Compute Transform Tree** ノードの **parentPrim** フィールドで指定します。

Compute ノードの `parentPrim` に `Camera_1` を追加し、シミュレーションを Stop → Play すると、`/base_link` の Transform が `Camera_1` 基準になったことを確認できます（プロパティ変更は Stop / Play を挟んで反映させます）。

## ステップ 2：オドメトリのセットアップ

ロボットのオドメトリを使うには、オドメトリの ROS メッセージ（`/odom`）と対応する TF を配信します。

1. [チュートリアル 1](01_urdf_import_turtlebot.md) でインポートした Turtlebot3 は、`/World/tb3_burger_processed/Geometry/base_footprint/base_link` に **Articulation Root API** が、`/World/tb3_burger_processed` に **IsaacRobotAPI**（`isaac:physics:robotLinks` 設定済み）が適用されているため、アーティキュレーションルートの手動設定は不要です。（任意の練習）ROS2 Publish Transform Tree に接続した Isaac Compute Transform Tree ノードの `targetPrims` に `/World/tb3_burger_processed` を追加すると、固定・可動を問わず全リンクの Transform が `/tf` に配信されることを確認できます。
2. Stage パネルでロボットのメインプリム `/World/tb3_burger_processed` を選択します。ロボットの状態を配信するグラフ（オドメトリ、TF ツリー、グラウンドトゥルース姿勢など）はロボットのアーティキュレーション全体に作用するため、個別のリンクではなく**ロボットのルート直下**に置くのが適切です。**Window > Graph Editors > Action Graph** で **New Action Graph** をクリックし、グラフ名を `ROS_OdomTF` にします（グラフのパスは `/World/tb3_burger_processed/ROS_OdomTF`）。
3. 次の画像に一致する Action Graph を構築します：

    ![オドメトリグラフ](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_6.0_ros_tut_gui_ros2_odometry_graph.png)

4. **Isaac Compute Odometry Node** の Property タブで、**Chassis Prim** に Turtlebot のプリム（`/World/tb3_burger_processed`）を追加します。このノードは**開始位置を基準としたロボットの位置**を計算し、出力は `/odom` トピックのパブリッシャと、`odom` → `base_link` の単一 Transform を配信する TF パブリッシャの両方に渡されます。
5. **ROS2 Publish Raw Transform Tree** ノードの Property タブで：
    - **childFrameId** を `base_link` に設定
    - **parentFrameId** を `odom` に設定

    これで TF ツリーに `odom -> base_link` が配信されます。

6. **ROS2 Publish Odometry** ノードの Property タブで：
    - **chassisFrameId** を `base_link` に設定
    - **odomFrameId** を `odom` に設定

!!! note "オドメトリの速度は完全な 3D で配信される"
    ROS2 Publish Odometry ノードは、並進速度・角速度とも **x, y, z の 3 成分すべて**を配信します。平面移動ロボットでも、ロボットの運動状態のより完全な表現が得られます。

7. この時点では TF ツリーは `odom -> base_link` だけです。`base_link` 配下のロボットの各リンクも追加するため、**Isaac Compute Transform Tree** ノードと **ROS2 Publish Transform Tree** ノードをグラフに追加します。Compute ノードの出力（execOut・parentFrames・childFrames・translations・orientations）を Publish ノードの同名入力に接続し、Publish ノードの Exec In・Context・Timestamp は他のノードと同様に接続します。
8. 追加した **Isaac Compute Transform Tree** ノードの Property タブで：
    - **parentPrim** を `/World/tb3_burger_processed/Geometry/base_footprint/base_link` に設定
    - **targetPrims** に次のプリムを設定：
        - `/World/tb3_burger_processed/Geometry/base_footprint`
        - `/World/tb3_burger_processed/Geometry/base_footprint/base_link/base_scan`
        - `/World/tb3_burger_processed/Geometry/base_footprint/base_link/caster_back_link`
        - `/World/tb3_burger_processed/Geometry/base_footprint/base_link/imu_link`
        - `/World/tb3_burger_processed/Geometry/base_footprint/base_link/wheel_left_link`
        - `/World/tb3_burger_processed/Geometry/base_footprint/base_link/wheel_right_link`

    !!! tip "targetPrims はロボットルートの指定でも OK"
        `/World/tb3_burger_processed` には IsaacRobotAPI が適用され `isaac:physics:robotLinks` が設定されているため、上の明示的なリストの代わりに `/World/tb3_burger_processed` を 1 つ追加するだけでも、アーティキュレーションチェーン全体が配信されます。

9. 最後に `world -> odom` を配信します。**この手順はロボットのグラウンドトゥルース自己位置が欲しい場合にのみ必要**です。通常、グローバルフレームと `odom` フレームの間の変換は [Nav2 AMCL](https://index.ros.org/p/nav2_amcl/) などの自己位置推定パッケージが担当します。グラウンドトゥルース自己位置をセットアップするには、もう 1 つ **ROS2 Publish Raw Transform Tree** ノードを追加し、同様に接続した上で：
    - **childFrameId** を `odom` に設定
    - **parentFrameId** を `world` に設定
    - **Translation / Rotation** は未接続のままにします。既定値（並進 (0, 0, 0)、回転クォータニオン (1, 0, 0, 0)）が使われ、これはロボットの**開始姿勢**に対応します。ロボットが別の位置から開始する場合は、その姿勢に合わせて更新してください。

最終的なグラフが次と一致することを確認します：

![オドメトリグラフ（最終形）](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_6.0_ros_tut_gui_ros2_odometry_TF_graph_final.png)

**Play** を押し、新しい ROS ターミナルで TF ツリーを PDF に出力して確認します：

```bash
ros2 run tf2_tools view_frames
```

生成された PDF を開き、Isaac Sim から配信している TF ツリーが次のようになっていることを確認します：

![TF ツリービュー](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_4.5_ros_tut_gui_ros2_odometry_graph_tf_tree_view.png)

!!! tip "完成例のシーン"
    Turtlebot の ROS 2 チュートリアルで登場するすべてのパブリッシャ／サブスクライバをセットアップ済みのシーンが、Content ブラウザの **Isaac Sim > Samples > ROS2 > Scenario > turtlebot_tutorial.usd** にあります。

## グラフショートカット

**TF パブリッシャ** — **Tools > Robotics > ROS 2 OmniGraphs > TF Publisher**。ポップアップで次を指定します：

- Graph Path と（あれば）Node Namespace
- **Target Prim**：アーティキュレーションチェーン全体を配信したい場合はアーティキュレーションルート API を含むプリム、単一の Transform を配信したい場合は個別のプリム
- **Parent Prim**：Transform の基準フレーム（既定は `/World`、ステージ上の任意のフレームを指定可能）

既存の TF パブリッシャに配信対象を追加したい場合、基準プリムが同じなら **Add to an existing graph** と **Add to an existing node** の両方にチェックを入れ、グラフ・ノードのパスと追加したいターゲットプリムを指定します。同じグラフでも基準プリムが異なる場合は新しい Transform ノードが作られ、既存の tick／コンテキスト／タイムスタンプノードが再利用されます。

**オドメトリパブリッシャ** — **Tools > Robotics > ROS 2 OmniGraphs > Odometry Publisher**。Graph Path・Node Namespace のほか、Articulation Root API を含むプリムと、オドメトリ計算の原点となるシャーシプリムを指定します。

## Isaac Sim 内で TF ツリーを可視化する（TF Viewer）

Isaac Sim の Transform Viewer を使うと、Isaac Sim や外部の ROS 2 ノードが配信する TF ツリー（`/tf`、`/tf_static`）を、**ビューポート内のシーンに直接描画**できます。RViz を起動しなくても TF を確認できる便利なツールです。

1. Extension Manager で `isaacsim.ros2.tf_viewer` を検索してエクステンションを有効化します。
2. メニューの **Window > TF Viewer** で制御ウィンドウを開きます。

    ![TF Viewer ウィンドウ](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_4.5_ros_tut_gui_ros2_tf_viewer_window_legend.png)

ウィンドウでは次を設定できます：

- 変換の計算基準となるフレーム
- フレーム（マーカー）の表示・色・サイズ
- フレーム名の表示・文字色・サイズ
- フレームの軸表示（RGB → XYZ 軸）・軸の長さ（m）・太さ
- 子フレームと親フレームの接続線の表示・色・太さ
- 変換の更新頻度（Hz）— 高くするとシミュレーション性能が低下する場合があります
- **Reset** ボタン — 変換バッファのクリア（`TF_OLD_DATA` 警告の解消などに有効）

3. 可視化を開始するには、配信されている TF ツリーの仕様に合わせて、計算基準のルートフレーム（例：`World` または `world`）を選択します。

![TF Viewer の表示例](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_4.5_ros_tut_gui_ros2_tf_viewer_example.png)

!!! tip "TF Viewer に何も表示されないとき"
    `/tf` や `/tf_static` に配信があるのに可視化（または特定のルートフレーム）が表示されない場合：

    - TF Viewer ウィンドウを開く前にシミュレーションを再生しておく
    - TF Viewer ウィンドウを閉じて開き直し、購読を更新する
    - **Reset** ボタンで変換ツリーをリセットする

    なお、TF Viewer ウィンドウを閉じると表示は停止し、ビューポートの描画はクリアされます。

## 複数センサーを RViz2 でまとめて表示する

!!! note "Windows / WSL での RViz2"
    Windows 11 では、マシンの構成によって、帯域を大きく使うトピックは WSL 内の RViz2 で可視化できない場合があります。

複数のセンサーを RViz2 で同時に表示するには、すべてのメッセージのタイムスタンプが正しく同期されている必要があります。ポイントは 3 つです。

**1. シミュレーションタイムスタンプ** — すべてのパブリッシャノードのタイムスタンプには **Isaac Read Simulation Time** ノードの出力を使います。

**2. ROS 2 clock** — シミュレーション時刻を `/clock` トピックに配信します。グラフは[チュートリアル 3: ROS 2 Clock](03_clock.md) のとおりです。

**3. frameId と topicName の命名規約** — RViz がすべてのセンサーと TF ツリーを一度に認識できるよう、次の規約に従います。実例は Content ブラウザの **Isaac Sim > Samples > ROS2 > Scenario > turtlebot_tutorial.usd** で確認できます：

| ソース | frameId | nodeNamespace | topicName | type |
|---|---|---|---|---|
| カメラ RGB | (デバイス名)\_(データ種別) | (デバイス名)/(データ種別) | image_raw | rgb |
| カメラ深度 | (デバイス名)\_(データ種別) | (デバイス名)/(データ種別) | image_rect_raw | depth |
| Lidar | base_scan | — | scan | laser_scan |
| Lidar | base_scan | — | point_cloud | point_cloud |
| TF | — | — | tf | tf |

シミュレーションを再生した状態で、設定済みの RViz を開きます：

```bash
ros2 run rviz2 rviz2 -d <ros2_ws>/src/isaac_tutorials/rviz2/camera_lidar.rviz
```

RViz ウィンドウの読み込みが終わったら、左側の **Display** パネルで各センサーストリームの表示を切り替えられます。

![複数センサーの RViz 表示](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_4.5_ros_tut_external_rtx_lidar_multisensor_rviz2.png)

!!! warning "RViz2 の use_sim_time を忘れずに"
    RViz2 ノードを起動したら、`use_sim_time` パラメータを true に設定してください。RViz2 が Lidar のデータ点の位置を補間する際などに、シミュレーションデータと同期するために必要です：

    ```bash
    ros2 param set /rviz use_sim_time true
    ```
