# ROS2 Transform Trees and Odometry

!!! info "Preliminary version"
    This is a concise English version. See the Japanese page for the full detailed walkthrough.

## Learning Objectives

Publish camera poses to the TF tree, publish relative poses, set up robot odometry, visualize multiple sensors in RViz2, and view the TF tree inside Isaac Sim.

In Isaac Sim 6.0, **ROS2 Publish Transform Tree** consumes pre-computed frames from an **Isaac Compute Transform Tree** node (`isaacsim.core.nodes`) instead of resolving prims internally — direct `targetPrims` input on the publish node is deprecated. **ROS2 Publish Raw Transform Tree** still publishes one parent→child transform, for logical frames like `odom -> base_link`.

## Transform Tree Publisher

Select `/World` in the Stage panel and create a graph named `ROS_CameraTF` (`/World/ROS_CameraTF`). Add an **Isaac Compute Transform Tree** node and a **ROS2 Publish Transform Tree** node; wire On Playback Tick → Compute `execIn`, Isaac Read Simulation Time → Publish `timeStamp`, and Compute outputs `execOut`/`parentFrames`/`childFrames`/`translations`/`orientations` into the matching Publish inputs. Put `Camera_1`/`Camera_2` in the **Compute node's** `targetPrims`, verify with `ros2 topic echo /tf`. Transforms default to the world frame; set `parentPrim` on the Compute node (e.g. `Camera_1`) for relative transforms (stop/play between property changes). If the wrong root link is chosen for an articulated robot, delete the Articulation Root in Raw USD Properties and re-add it (+ADD > Physics > Articulation Root) on the desired prim, then save and reload.

## Setting Up Odometry

1. No manual articulation-root setup is needed: the imported Turtlebot has ArticulationRootAPI on `/World/tb3_burger_processed/Geometry/base_footprint/base_link` and IsaacRobotAPI (with `isaac:physics:robotLinks`) on `/World/tb3_burger_processed`.
2. Select `/World/tb3_burger_processed` and create a graph named `ROS_OdomTF` at the robot root. Build the odometry graph: **Isaac Compute Odometry Node** (Chassis Prim = `/World/tb3_burger_processed`; computes pose relative to start) feeding a **ROS2 Publish Odometry** node (chassisFrameId `base_link`, odomFrameId `odom`) and a **ROS2 Publish Raw Transform Tree** (parent `odom`, child `base_link`). The odometry message carries full 3D linear and angular velocity.
3. Add an **Isaac Compute Transform Tree** + **ROS2 Publish Transform Tree** pair with parentPrim `/World/tb3_burger_processed/Geometry/base_footprint/base_link` and targetPrims for base_footprint, base_scan, caster_back_link, imu_link, wheel_left_link, wheel_right_link (under `Geometry/base_footprint[/base_link]`) — or simply target `/World/tb3_burger_processed`, since IsaacRobotAPI expands the full articulation chain.
4. Optional ground-truth localization: another Raw TF node with parent `world`, child `odom` (defaults = start pose). Normally a localization package such as Nav2 AMCL provides this transform.

Verify with `ros2 run tf2_tools view_frames`.

![Final odometry graph](https://docs.isaacsim.omniverse.nvidia.com/latest/_images/isim_6.0_ros_tut_gui_ros2_odometry_TF_graph_final.png)

Menu shortcuts: **Tools > Robotics > ROS 2 OmniGraphs > TF Publisher / Odometry Publisher**.

## Multiple Sensors in RViz2

Feed all publishers' timestamps from **Isaac Read Simulation Time**, publish `/clock`, and follow the frameId/topicName conventions (camera: `(device)_(type)` frame, `image_raw`/`image_rect_raw` topics; lidar: `base_scan` frame, `scan`/`point_cloud` topics). Sample: `turtlebot_tutorial.usd`. Open the provided config with `rviz2 -d <ros2_ws>/src/isaac_tutorials/rviz2/camera_lidar.rviz` and set `ros2 param set /rviz use_sim_time true`.

## TF Viewer

Enable `isaacsim.ros2.tf_viewer`, open **Window > TF Viewer**, choose the root frame — the published `/tf` / `/tf_static` tree is drawn directly in the viewport. If nothing shows: play the sim first, reopen the window, or press Reset.
